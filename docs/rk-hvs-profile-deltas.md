# Proposed claim changes for the Rk3588, HVS5 and HVS6 profiles

Written 2026-11-28 (host UTC) on the host. No board was used and no code was run or changed. This is input for the later item `profile-tighten`: one row per claim of the three profiles, with the evidence that exists in this tree, its tag, and a proposal.

The claims are those of `crates/composition-drm/src/profile/rk3588.rs` (`DriverProfile::Rk3588Vop2`) and `crates/composition-drm/src/profile/vc4.rs` (`DriverProfile::Vc4Hvs5`, `DriverProfile::Vc4Hvs6`), read at the integration tip. Whatever `profile.rs` states about them is repeated there, so those two files are the whole claim set.

## Tags and rules

- **observed 2026-11-28** (or another date) = measured on a board and recorded in a dated session or observed doc named in the row. A row cites a date only when the linked doc carries it. This brief measured nothing.
- **read from source** = stated by a source doc at the pin that doc names (mainline `v6.18` and `v6.18.55` for RK3588; `rpi-6.18.y` at `16ae2649dcfadf9d81445b1177a3191efa3cb82e` and `rpi-6.12.y` for vc4).
- **inferred** = concluded from rows, not seen and not stated.
- Proposals are `keep`, `tighten to X`, or `wait for <item>`. A change that needs `MAX_PLANES` or `MAX_FORMATS` raised is not a profile proposal: it is listed under "Composition-core findings" and is the owner's decision.
- **No `vc4-hvs-session-*.md` exists on this tip.** The RPi5 and reTerminal sessions (`rpi5-hvs6-scale-session`, `cm4-hvs5-scale-session`, `rpi5-hvs6-session`, `cm4-hvs5-session`) have not merged. Every HVS row that depends on them says `wait for` that item. The same holds for the RK items `t6-sweep-session`, `t6-commit-session` and `t6-zpos-session`, which have no session doc either.
