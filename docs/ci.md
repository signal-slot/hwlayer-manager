# Continuous integration

`.github/workflows/ci.yml` (workflow `ci`, job `checks`) runs on every pull request to `main` and every push to `main`, on `ubuntu-latest`, with the latest stable Rust and the committed `Cargo.lock`. It runs `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace`, which also compiles and runs the C tests with the runner's `cc` and checks the freestanding backend object with `nm`. It then builds `composition-core` for `thumbv7em-none-eabihf`, and builds the static library for the same target without `std`, with `panic-handler`, in release. Last, it cross-builds for aarch64 Linux with `scripts/cross-aarch64.sh --locked` (target `aarch64-unknown-linux-musl`, static, linked by `rust-lld`, so no aarch64 gcc is needed): the `composition-drm` library, its `probe` example, and the `drm-harness` binary of `composition-drm-harness` (`tools/drm-harness`). This step only compiles and links; it runs nothing, on the runner or on a board, so it shows that the Linux i.MX95 builds compile, not that they work. It does not run the vkms tests: they stay ignored, and `scripts/vkms-vm-test.sh`, which boots a kernel in QEMU, is not part of CI. It builds and runs nothing on a board, does not compile the C backend for Arm, and does not test the minimum Rust version (the `rust-version` of `Cargo.toml`). Hardware milestones are never claimed from it. A green run means the host tests and the bare-metal Rust builds pass, and says nothing about hardware.
