# SoW traceability: deliverables and milestone criteria to repository evidence

Written 2026-11-28 and updated 2026-11-28 to the repository at commit `04afff7`. It covers every deliverable named in `SoW.md` §8 (WP0 to WP5) and every acceptance condition of §9 (M1 to M3), and lists the files that address each one. It adds no result of its own. Every status comes from what another document of this repository records, and that document is named in the row. Where this file and the named document disagree, the named document is right.

Status values:

- **observed &lt;date&gt;**: a document of this repository records a board observation made on that date.
- **host only**: the item exists in the repository and was checked on a development host only, by build, host tests, desk reading or vkms (a virtual kernel driver, not hardware). No board evidence exists.
- **planned**: files, a test plan or an assigned plan item exist, but the result does not.
- **not started**: nothing in the repository addresses it yet.

At this commit these documents record board observations:

- **i.MX95 Linux (M1 work).** `docs/m1-imx95-report.md` summarises board runs of 2026-11-27 and 2026-11-28 on the Verdin iMX95 (master descriptor, kernel lease and drm-lease-manager runs, a topology probe). Detail: `docs/m1-imx95/master-run.md`, `docs/m1-imx95/lease-run.md`, the probe `docs/imx95-probe-2026-11-28.txt`. That report states its own verdicts. **This file does not restate or adopt any milestone verdict**: the M1 rows below name the report and say what it observed, with the gaps it lists.
- **i.MX95 Zephyr (M2 work).** `docs/imx95-zephyr/observed-2026-11-27.txt` and `docs/imx95-zephyr/observed-2026-11-28.txt`, two read-only snapshots (remoteproc, device tree, SM/SCMI dmesg, clocks, power domains; the second file also DPU interrupt counts, panel timing, SoC revision and the SM/SCMI version) of the Verdin iMX95. Both come from a board run dated 2026-11-27 and are tagged observed 2026-11-27. They say what Linux holds today. Neither is a scanout, VSYNC, latch or composition result, so neither meets a milestone condition.
- **Other SoCs** (`docs/observed/`, `docs/linux-board-scenarios.md`): dated observations of BCM2711, BCM2712, RK3588, STM32MP257 and i.MX8M Plus (`docs/observed/imx8mp-x2-2026-11-28/`, 2026-11-28), outside the milestones (`docs/open-issues.md` X-07).

No document records an AM62P board observation.

**M2 work is on `main` at this commit as source studies, design notes, host builds and QEMU runs.** The Zephyr applications `tests/board/imx95_m7/`, `tests/board/imx95_m7_scanout/` and `tests/board/imx95_m7_engine/` are host builds only and have never run on the i.MX95 (their READMEs say so); `tests/zephyr/qemu_engine/` and `tests/zephyr/display_dummy/` ran under QEMU, which emulates another core and is not hardware. `docs/imx95-zephyr-feasibility.md` records the remoteproc gate as not met and the M7 run as skipped on 2026-11-28, not failed (`docs/open-issues.md` M2-08). ## Keeping this file current

Change a status only when the document named in its row records the new result, and name that document. A board result is written as **observed &lt;date&gt;** — a YYYY-MM-DD date like **observed 2026-11-27** — with the date the document gives. CI results, vkms runs and desk readings never raise a row above **host only** (`docs/ci.md`).
